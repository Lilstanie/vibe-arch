# 猎头工作流拆解与自动化分析

以 Jay 在 Boss 直聘找候选人为主线，把工作拆成三段，标注每步的**当前自动化程度**、
**本项目做到的程度**，以及**最值得投入的地方（best ROI）**。

## 全景

```
拿到 JD ──▶ ① 岗位分析 ──▶ ② 触达 & 匹配 ──▶ ③ 沟通 & 流程管理 ──▶ 闭环沉淀
             (寻访策略)      (搜/招呼/初筛)      (电话/约面/跟进)      (人才池激活)
```

---

## ① 岗位分析：JD → 寻访策略

| 步骤 | 现状（手动） | 本项目 | 自动化 |
|---|---|---|---|
| 读懂 JD 硬性要求 / 红线 | Jay 凭经验 | AI 拆出 hard_requirements / red_lines | 高 |
| 生成 Boss 搜索关键词 + 布尔串 | 手打标签 | AI 产出 keywords + boolean_string | 高 |
| 对标挖人公司 | 经验 | AI 建议 target_companies | 中 |
| 初筛问题清单 | 临场发挥 | AI 产出 screening_questions | 高 |

**要点**：这一步是后面所有匹配的"标尺"。标尺一旦结构化（`job.analysis`），
匹配/初筛/话术都能引用它，避免每次 Jay 重复描述需求 → 也是**防上下文污染**的关键：
需求作为结构化数据注入，而不是塞进一个越滚越长的对话里。

## ② 触达 & 匹配（**最花时间 / best ROI**）

> Jay 的原话：最花时间、ROI 最高的是「在 Boss 聊到更多、更准的人」。

难点拆解：

1. **推荐/搜索依赖关键词与标签** —— 关键词来自 Jay 的经验，质量参差。
   - 本项目：岗位分析自动产出关键词 + 布尔串，减少 Jay 拍脑袋。
   - 进阶：把 Jay 手头所有信息（JD、历史成功候选人画像、拒绝理由）一起喂给 AI，
     反推更精准的搜索词与筛选条件（见 ROADMAP「智能寻访」）。
2. **筛选条件多、简历看不过来** ——
   - 本项目：`screen-resume` 先抽字段给出初筛判断；**Jay 自己 preview，拿不准的才喂 LLM**
     （`needs_human` 标记），既省 token 又保留人的判断。
   - 简历数据落到飞书 Table 2（见 MCP-FEISHU）。
3. **打招呼有每日限额（约 20–30 条）** ——
   - 策略：**优先给高匹配候选人打招呼**。匹配分排序 → 限额花在刀刃上。
   - 话术：AI 生成 2 版开场白，突出候选人量化亮点，降低群发感。
   - 自动化：`extension/` 提供半自动填充 Boss 聊天框的内容脚本骨架
     （**尽量手动**：填好等 Jay 确认发送，不做无人值守群发，规避风控与体验风险）。

**ROI 结论**：把「岗位分析 → 匹配排序 → 优先级打招呼 → 初筛」串成一条流水线，
让 Jay 的有限额度和注意力落在最可能成的人身上，是投入产出比最高的一段。

## ③ 沟通 & 流程管理

| 步骤 | 现状 | 本项目 | 自动化 |
|---|---|---|---|
| 候选人状态管理 | Excel / 脑子 | Kanban 看板 + 阶段流转 + 审计流 | 高 |
| 电话沟通记录 | 手写 | 转写 → AI 纪要（意向/要点/顾虑） | 高 |
| 电话后待办 | 容易忘 | 纪要自动生成**带时间**的跟进任务 | 高 |
| 主动跟进 / 人才池激活 | 靠记性 | 提醒系统（今晚/明天/本周末 → 时间戳） | 中高 |

**电话转文字**：语音转写文本 + （可选）附简历一起喂 LLM →
输出 summary / 意向等级 / concerns / **suggested_actions（含 due_hint）** → 落成提醒。
时区按服务器本地，`due_hint` 用自然语言解析（见 `api.js hintToDue`）。

**人才池激活**：库里躺着的候选人，定期按「岗位新开 / 到某时间点」批量再激活。
当前提供手动提醒；批量激活规则见 ROADMAP。
