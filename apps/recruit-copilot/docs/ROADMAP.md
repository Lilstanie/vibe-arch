# 路线图：70% → 80% → 更高自动化

产品形态按「自动化程度」分档演进。每档都能独立交付价值。

## 现在（prototype，约 70% 的"笨办法" + 结构化）

- ✅ JD 分析、候选人匹配、简历初筛、话术生成、通话纪要（无状态 AI Agent）
- ✅ 人才看板、跟进提醒、活动审计
- ✅ 话术**一键复制**，人工贴到 Boss（可靠但手动）
- ✅ 数据存本地 JSON

**特征**：AI 负责"想"，人负责"搬运"。稳、可控，但搬运环节费手。

## 里程碑 1 —— 打通飞书（→ 80%）✅ 已完成（写入侧）

- [x] 接 `integrations/feishu.js`：候选人 → Table 1，简历 → Table 2（幂等 upsert，带 record_id）
- [x] 入库 / 匹配 / 阶段流转自动同步飞书；匹配分、初筛结论一并回写
- [x] 可观测：同步日志 `GET /api/feishu/log`、状态 `GET /api/feishu/status`、抽屉内手动「同步到飞书」
- [x] dry-run 兜底：无凭证时记录"将写入的内容"，配好 `FEISHU_APP_ID/SECRET/BITABLE_APP_TOKEN` 自动转真实写入
- [x] 双向回流：飞书里改阶段/备注 → `POST /api/feishu/pull` 拉回本系统（顶栏「↻ 拉取飞书」；抽屉「🧪 模拟回流」演示整条往返）
- [ ] 生产化：用飞书事件订阅（webhook）替代手动拉取做实时回流
- **价值**：结论自动沉淀 + 双向一致，Jay 不再手抄进表格。见 [MCP-FEISHU.md](MCP-FEISHU.md)。

## 集成形态取舍

| 形态 | 优点 | 代价 |
|---|---|---|
| Web 工作台（本项目） | 功能全、看板/纪要顺手 | 与 Boss 页面分离，需切窗口 |
| Chrome 扩展侧边栏 | 贴着 Boss 页面，就地操作 | 受平台 DOM/风控约束 |
| 飞书 MCP / 机器人 | 结论沉淀在团队协作空间 | 需企业配置 |

**建议**：三者组合——扩展做"就地触达"，Web 做"深度分析与看板"，飞书做"沉淀与协作"。
本仓库已为三者都留了接口。
