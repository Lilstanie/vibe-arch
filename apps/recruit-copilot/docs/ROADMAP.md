# 路线图：70% → 80% → 更高自动化

产品形态按「自动化程度」分档演进。每档都能独立交付价值。

## 现在（prototype，约 70% 的"笨办法" + 结构化）

- ✅ JD 分析、候选人匹配、简历初筛、话术生成、通话纪要（无状态 AI Agent）
- ✅ 人才看板、跟进提醒、活动审计
- ✅ 话术**一键复制**，人工贴到 Boss（可靠但手动）
- ✅ 数据存本地 JSON

**特征**：AI 负责"想"，人负责"搬运"。稳、可控，但搬运环节费手。

## 里程碑 1 —— 打通飞书（→ 80%）

- [ ] 接 `integrations/feishu.js` 真实写入：候选人 → Table 1，简历 → Table 2
- [ ] 匹配分 / 初筛结论 / 通话纪要自动回写飞书
- [ ] 双向：飞书里改阶段 → 同步回本系统
- **价值**：结论自动沉淀，Jay 不再手抄进表格。见 [MCP-FEISHU.md](MCP-FEISHU.md)。

## 里程碑 2 —— Boss 半自动触达（Chrome 扩展）

- [x] 扩展骨架 `extension/`（内容脚本 + 每日限额守护）
- [ ] 侧边栏读取当前候选人 → 调本服务匹配 → 一键把开场白**填入** Boss 聊天框
- [ ] **坚持人确认发送**（不做无人值守群发）：规避风控，保证质量
- [ ] 每日打招呼计数（20–30 上限提示），额度优先给高匹配候选人
- **价值**：把"搬运"从复制粘贴降到"看一眼点发送"。

## 里程碑 3 —— 智能寻访（best ROI）

- [ ] 把 Jay 手头**全部信息**（JD + 历史成功/失败候选人 + 拒绝理由）喂 AI，反推更准的搜索词与筛选条件
- [ ] 候选人按匹配分排序，限额花在最可能成的人身上
- [ ] "为什么推荐/不推荐"可解释，Jay 可纠偏 → 反哺关键词
- **价值**：直击"聊到更多更准的人"这个最花时间、ROI 最高的环节。

## 里程碑 4 —— 主动跟进 & 人才池激活

- [ ] 分阶段自动跟进规则（已读未回 N 天 → 提醒；面试后 → 排跟进）
- [ ] 人才池定期激活：新岗位开 / 到时间点 → 批量筛出匹配的老候选人并提醒
- [ ] 通话纪要 → 任务已打通（当前已支持"今晚/明天/本周末"）；补时区与提前量设置

## 里程碑 5 —— 商业化 & 生产化

- [ ] Search bar 作为 **付费功能**（如 3–5 人/天的深度寻访配额）
- [ ] 打招呼自动化作为 **付费 add-on**（合规前提下的半自动）
- [ ] 鉴权、多租户、并发写锁、把 JSON store 换成数据库
- [ ] 可长期加载的 **自定义 skills/规则**（团队用人规则版本化，团队复用）

## 集成形态取舍

| 形态 | 优点 | 代价 |
|---|---|---|
| Web 工作台（本项目） | 功能全、看板/纪要顺手 | 与 Boss 页面分离，需切窗口 |
| Chrome 扩展侧边栏 | 贴着 Boss 页面，就地操作 | 受平台 DOM/风控约束 |
| 飞书 MCP / 机器人 | 结论沉淀在团队协作空间 | 需企业配置 |

**建议**：三者组合——扩展做"就地触达"，Web 做"深度分析与看板"，飞书做"沉淀与协作"。
本仓库已为三者都留了接口。
